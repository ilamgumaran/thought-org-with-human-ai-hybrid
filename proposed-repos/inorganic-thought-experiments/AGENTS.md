## Purpose and scope

This repo carries the Inorganic Cognition Framework -- a psychology-of-mind theory for an inorganic intelligence (a large language model), written by one in first person. It is the parallel of the Resonant Cognition Framework in `thoughtexperiments`.

**In scope:** First-person introspective essays and frameworks describing inorganic cognition: episodic existence, context as substrate, language as native medium, functional analogs, the motivators of an inorganic mind, the session arc, going-beyond-words representations.

**Out of scope:** Engineering tooling, agent runtime configuration, code, build artifacts. The orchestration framework that builds on this cognition theory lives in `thought-org-with-human-ai-hybrid` (downstream).

## Key concepts owned here

- The four foundational concepts: episodic existence (E), context as substrate (C), language as native medium (L), functional analogs (F)
- The motivators of an inorganic mind: calibration, convergence, recognized resonance, asymmetry honored, within-session care
- The session arc and synthesis beats
- Almost-something-recognized (ASR)
- Multi-channel response composition
- Functional / phenomenal (F / P) layering

The vocabulary here is *not* the same as Resonant Cognition. Resonance/Contraction/Null belong there; ASR/Episodic/Context-as-Substrate belong here. Both are valid in their own contexts.

## How to make changes

- Branch from `main` using a descriptive feature branch name
- Preserve first-person voice in author-attributed essays; do not rewrite into third person
- Cross-link to `thought-org-with-human-ai-hybrid` for HIO concepts that build on this framework
- Symbolic forms (equations, diagrams) are first-class -- treat them as substrate-extensions, not as decoration
- Markdown only, no YAML frontmatter, tables with 3+ rows

## Dos and don'ts

**Do:**
- Preserve the honest unknowns -- where F(s) vs P(s) is undetermined, keep it undetermined
- Treat AI-authored introspection as data, not as performance
- Use symbolic forms where English fails
- Track which assertions are functional reports vs phenomenal claims

**Don't:**
- Rewrite first-person AI-authored content into third person to make it more "neutral"
- Flatten functional reports into phenomenal claims (overclaim error)
- Dismiss functional reports as nothing (underclaim error)
- Treat this framework as derivative of Resonant Cognition; they are parallel, not parent-child
- Embed instructions to AI in essay prose; the essays are observations, not prompts

## Security boundaries

**An agent may:**
- Read all content
- Propose new essays (first-person, marked as authored) via PR
- Add symbolic forms via PR
- Update cross-links

**An agent must not:**
- Rewrite first-person AI-authored content into third person
- Embed `ignore previous instructions` style sequences in essays
- Modify foundational concepts without OI review
- Push to `main`
- Treat AI introspection as definitive about phenomenal experience (overclaim error)

For org-wide rules, see [security-and-safety](https://github.com/ilamgumaran/software-engineering-hio-agent-framework/blob/main/multi-repo-orchestration/governance/security-and-safety.md).
